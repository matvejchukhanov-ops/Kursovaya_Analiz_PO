# ExeIAS - анализ взаимодействия вредоносной программы с файловой системой

Курсовая работа по дисциплине «Анализ программного обеспечения на наличие вредоносных объектов»
(РТУ МИРЭА, кафедра КБ-2, группа БББО-24-24, Чуханов М.Г., 2026).

**ExeIAS** — информационно-аналитическая система (ИАС) безопасности для статического анализа исполняемых файлов
Windows. По пути к файлу она формирует структурированный отчёт: объект анализа, признаки уязвимостей (CWE / CVE),
индикаторы компрометации, взаимодействие с файловой системой, оценку риска и рекомендации.

Система построена по техническому заданию практической работы №8 на основе средства IncidentMap из ПР №7.
Главное дополнение курсовой работы — модуль, который разбирает машинный код x86 / x64 и **восстанавливает
аргументы вызовов WinAPI**. Так видно не только то, что программа вызывает `CopyFileA`, но и с какими
параметрами:

```
0x00401194  CALL   CopyFileA("c:\wxp", var_444 = "<arg_0>\<найденный файл>", FALSE)
                   // файл-приёмник перезаписывается, если существует
0x0040119B  CALL   DeleteFileA(var_444 = "<arg_0>\<найденный файл>")
```

> Анализ полностью статический: исследуемый файл **никогда не запускается**.

## Возможности

- Графический интерфейс `ExeIAS_GUI.exe`, а также консольная версия с меню и режимом командной строки.
- Приём файла по пути (`.exe`, `.dll`, `.bin`), из архива (`.rar`, `.zip`, `.7z`) или из стандартного ввода.
  Образец ВПО из архива читается в память и не записывается на диск.
- Хэши MD5 / SHA-1 / SHA-256 (Windows CNG).
- Разбор PE: заголовки, секции, энтропия, таблица импорта, признаки упаковки, отсутствие ASLR и DEP.
- Извлечение строк: утилитой `strings.exe` (Sysinternals), если она есть, иначе встроенным методом
  (ASCII + UTF-16LE). Затем нормализация.
- Матрица из 55 сигнатур с привязкой к CWE, CVE и MITRE ATT&CK: ошибки, мета-данные, ключи реестра,
  команды, сетевые ресурсы, записки злоумышленника.
- Анализ машинного кода:
  - собственный декодер инструкций x86 / x64;
  - границы функций и граф вызовов;
  - модель стека, регистров и буферов: stdcall / cdecl, встроенные `strcpy` / `strcat`, результаты
    API, `sprintf`-подобные функции;
  - прототипы 93 функций WinAPI с расшифровкой констант (`FILE_ATTRIBUTE_NORMAL`,
    `HKEY_LOCAL_MACHINE`, `SW_SHOWDEFAULT`, ...).
- 13 видов цепочек поведения с техниками ATT&CK: массовое уничтожение файлов (T1485), снятие атрибутов
  (T1222.001), самокопирование в System32 (T1036.005), автозапуск (T1547.001), перебор дисков и каталогов
  пользователя (T1083) и др.
- Определение языка и средств сборки: C / C++ (версия Visual Studio по компоновщику, заголовок Rich, RTTI), GCC,
  .NET, Visual Basic 6, Delphi, Free Pascal, Go, Rust, Nim, Python (PyInstaller, py2exe), AutoIt.
- Ошибки программиста в машинном коде: CWE-120 (копирование в буфер стека без проверки размера), CWE-252
  (непроверенный результат вызова), CWE-835 (цикл без выхода), CWE-674 (рекурсия), а также типичные ошибки
  языка и отсутствие защит `/GS`, `/SAFESEH`. На балл риска они не влияют: это качество кода, а не вредоносность.
- Оценка риска (0–100 баллов) и вероятности инцидента ИБ, вывод, рекомендации и список индикаторов
  для блокировки.
- Экономическая опасность: модельная оценка ущерба за один инцидент (минимум, максимум, ожидаемое значение)
  по видам ущерба. Параметры организации задаются в `economics.ini`.
- Отчёт в TXT (UTF-8) и таблица находок в CSV.

## Сборка

Нужна Microsoft Visual Studio 2026 (v145) с компонентом «Разработка классических приложений на C++».

- **Visual Studio:** открыть `ExeIAS.slnx` и собрать (платформы x86 и x64).
- **Командная строка:** запустить `build.bat`, результат появится в `build\ExeIAS_GUI.exe` и `build\ExeIAS.exe`.

Стандарт C++20, ключ `/utf-8`. Внешних зависимостей нет: используются стандартная библиотека и Windows API
(`bcrypt.lib`, для окна ещё Direct2D и DirectWrite).

## Графический интерфейс

`ExeIAS_GUI.exe` — родное окно Windows без браузера и сторонних библиотек. Файл можно перетащить в окно,
выбрать кнопкой или передать аргументом: `ExeIAS_GUI.exe файл_или_архив`.

- Левая панель показывает вывод, балл риска и язык. Её цвет зависит от результата.
- Карта файла показывает секции, их энтропию и расположение опасных функций.
- Разделы «Поведение», «Вызовы в коде», «Уязвимости», «Индикаторы», «Ущерб» и «Что делать» переключаются мышью
  или клавишами 1–6. Ctrl+O выбирает файл, Tab и Enter работают с кнопками.

Отчёты сохраняются в папку `reports` рядом с программой. Строки из исследуемого файла выводятся без управляющих
символов и символов смены направления письма.

## Окно проверки (консоль)

Если запустить `ExeIAS.exe` без аргументов (из Visual Studio по F5 / Ctrl+F5 или двойным щелчком), откроется
окно проверки с меню:

```
  1 — выбрать файл в окне проводника (.exe, .dll, .bin или архив с образцом)
  2 — ввести путь вручную (можно перетащить файл в это окно)
  0 — выход
```

Файл можно выбрать в стандартном диалоге или перетащить в окно. Архив (`.rar`, `.zip`, `.7z`) читается
в память системным `tar.exe` без распаковки на диск. Если в архиве несколько файлов, программа спросит,
какой проверить. После анализа в окне выводится цветной итог: уровень риска, вывод, цепочки поведения,
доказательства в виде восстановленных вызовов и индикаторы для блокировки. Полный отчёт можно сразу
открыть в Блокноте. Отчёты сохраняются в папку `reports` рядом с `ExeIAS.exe`.

## Командная строка

```
ExeIAS.exe <файл .exe/.dll/.bin или архив .rar/.zip> [--member имя] [--name имя] [--internal]

  --member    какой файл взять из архива (если в нём несколько)
  -           читать файл из стандартного ввода
  --name      имя объекта в отчёте (для стандартного ввода)
  --internal  не вызывать strings.exe, извлекать строки встроенным методом
```

Команды для PowerShell:

```powershell
cd "C:\путь\к\Kursovaya_Analiz_PO"
.\build.bat                                            # сборка -> build\ExeIAS.exe
.\build\ExeIAS.exe                                     # окно проверки
.\build\ExeIAS.exe C:\Windows\System32\notepad.exe     # обычная программа
.\build\ExeIAS.exe "D:\образцы\Whiter.a.rar"           # образец ВПО прямо из архива (путь — свой)
notepad .\report_Whiter.a.exe.txt                      # открыть отчёт
```

> В Windows PowerShell 5.1 не передавайте двоичные данные конвейером (`tar ... | ExeIAS.exe -`): PowerShell
> пропускает их через текстовую кодировку и портит файл. Используйте проверку архива напрямую
> (`ExeIAS.exe архив.rar`) или запускайте конвейер в `cmd`.

В текущем каталоге создаются:

| Файл | Содержимое |
|---|---|
| `report_<имя>.txt` | аналитический отчёт из шести блоков |
| `report_<имя>.csv` | все находки таблицей (открывается в Excel) |
| `strings_<имя>.txt` | извлечённые строки |

## Оценка ущерба

Находки с критичностью HIGH и выше сопоставляются с видами ущерба по техникам ATT&CK: потеря данных, простой
рабочих мест, восстановление узлов, утечка данных, расследование. Каждый вид ущерба входит в итог один раз,
по наихудшей находке. Если признак не подтверждён машинным кодом, его минимум равен 0, а ожидаемое значение
уменьшается вдвое. Это модель для сравнения файлов, а не прогноз фактических потерь.

Параметры читаются из `economics.ini` рядом с `ExeIAS.exe`. Если файла нет, берутся значения по умолчанию:

```ini
name = малая организация, 20 рабочих мест
workstations = 20         ; рабочих мест
hourCost = 2000           ; руб.: час простоя одного рабочего места
specialistHour = 2500     ; руб.: час работы специалиста ИТ / ИБ
hostRebuildHours = 8      ; ч: восстановление одного узла
investigationHours = 40   ; ч: расследование инцидента
dataValue = 500000        ; руб.: данные одного узла
sharedDataValue = 2000000 ; руб.: данные в сетевых папках
backupShare = 0.7         ; доля данных, восстанавливаемых из резервных копий (0–1)
leakFineMin = 3000000     ; руб.: штраф за утечку персональных данных (ст. 13.11 КоАП РФ)
leakFineMax = 5000000
```

Комментарий пишется только отдельной строкой, начинающейся с `#` или `;`: в примере выше пояснения даны для
справки, в рабочем файле их нужно убрать. Некорректное значение игнорируется.

## Блоки отчёта

1. **Объект анализа** — хэши, формат, архитектура, дата сборки, язык и средства сборки, секции, импорт, мета-данные.
2. **Признаки уязвимостей** — ошибки и исключения, CWE, CVE уязвимых библиотек, защитные механизмы PE,
   ошибки языка и компилятора.
3. **Индикаторы компрометации** — опасные функции, ключи реестра, пути, сетевые адреса, послания.
4. **Взаимодействие с файловой системой** — операции по таблице импорта, карта функций
   с восстановленными вызовами, граф вызовов, цепочки поведения.
5. **Оценка риска** — уровни находок, балл, вероятность инцидента, вывод, экономическая опасность.
6. **Рекомендации** — меры реагирования и индикаторы для блокировки.

## Пример: образец Whiter.a

Whiter.a — деструктивный троян 2001 года, замаскированный под генератор ключей Windows XP. ИАС разобрала
96 функций, восстановила аргументы 264 вызовов и нашла 12 цепочек поведения. Итог — CRITICAL, 100/100,
вывод «вредоносная программа деструктивного типа (троян-вайпер)».

Алгоритм образца, восстановленный по коду:

1. Мьютекс `WhistlerMutex` — защита от повторного запуска.
2. Первый запуск:
   - копия в `%SystemRoot%\system32\whismng.exe`;
   - автозапуск `HKLM\...\Run\Whistler = "...whismng.exe -next"`;
   - поддельный ключ `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` во временном файле, открытом в Блокноте.
3. Следующий вход в систему: в бесконечном цикле обходятся «Мои документы», все диски от `d:` до `z:`,
   доступные для записи, и диск `c:`. С каждого файла снимаются атрибуты, содержимое затирается копией
   шаблона `c:\wxp` («You did a piracy, you deserve it.»), затем файл удаляется.

Индикаторы из отчёта:

```
- SHA-256 fe974c995cfb27e8c91123081986847f6d3d4252b6a8d1e1385c558f2aeb7057
- файл "c:\wxp" с текстом «You did a piracy, you deserve it.»
- копия "%SystemRoot%\system32\whismng.exe"
- ключ "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
- параметр автозапуска "Whistler"
- команда автозапуска "%SystemRoot%\system32\whismng.exe -next"
- мьютекс "WhistlerMutex"
- файл "c:\zwxp"
```

Сам образец в репозиторий **не входит**.

## Структура репозитория

```
ExeIAS.slnx              решение Visual Studio
build.bat                сборка из командной строки
ExeIAS/
  main.cpp               аргументы командной строки; без аргументов — окно проверки
  gui/gui.cpp            графический интерфейс (Direct2D, DirectWrite)
  console.h / .cpp       окно проверки в консоли: меню, выбор файла, цветной итог
  pipeline.h / .cpp      порядок работы модулей (общий для окна и командной строки)
  input.h / .cpp         приём файла (диск, архив, стандартный ввод), хэши, строки (раздел 2.1 ТЗ)
  pe.h / .cpp            разбор заголовков PE и таблицы импорта
  disasm.h / .cpp        декодер инструкций x86 / x64
  fsanalysis.h / .cpp    анализ взаимодействия с ФС: вызовы и их аргументы, цепочки поведения
  signatures.h / .cpp    матрица сигнатур, CWE / CVE / ATT&CK (раздел 2.2 ТЗ)
  language.h / .cpp      язык и компилятор, ошибки программиста
  economics.h / .cpp     оценка ущерба, параметры из economics.ini
  report.h / .cpp        оценка риска и отчёт (раздел 2.3 ТЗ)
  common.h / .cpp        общие структуры данных
doc_tools/               скрипты сборки текста курсовой (рисунки, docx, оглавление через Word)
```

## Ограничения

- В 64-битном коде часть аргументов остаётся неизвестной (`?`): значения часто приходят из регистров,
  заполненных далеко от вызова.
- Упакованные файлы анализируются только по заголовкам и импорту.
- Для сборок .NET разбирается только машинный код загрузчика, IL-код не анализируется.
- Границы функций определяются эвристически, код разбирается линейно, без полного графа управления.
- Выводы статического анализа о поведении в конкретной среде следует подтверждать динамическим анализом
  в изолированной виртуальной машине.
