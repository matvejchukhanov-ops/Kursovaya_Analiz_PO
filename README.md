# ExeIAS — анализ взаимодействия вредоносной программы с файловой системой

Курсовая работа по дисциплине «Анализ программного обеспечения на наличие вредоносных объектов»
(РТУ МИРЭА, кафедра КБ-2, группа БББО-24-24, Чуханов М.Г., 2026).

**ExeIAS** — информационно-аналитическая система (ИАС) безопасности для статического анализа исполняемых файлов
Windows. По пути к файлу она формирует структурированный отчёт: объект анализа, признаки уязвимостей (CWE / CVE),
индикаторы компрометации, взаимодействие с файловой системой, оценку риска и рекомендации.

Система построена по техническому заданию практической работы №8 на основе средства IncidentMap из ПР №7.
Главное дополнение курсовой работы — модуль, который разбирает машинный код x86 / x64 и **восстанавливает
аргументы вызовов WinAPI**. Так видно не только то, что программа вызывает `CopyFileA`, но и с какими
параметрами:

```
0x00401194  CALL   CopyFileA("c:\wxp", var_444 = "<arg_0>\<найденный файл>", FALSE)
                   // файл-приёмник перезаписывается, если существует
0x0040119B  CALL   DeleteFileA(var_444 = "<arg_0>\<найденный файл>")
```

> Анализ полностью статический: исследуемый файл **никогда не запускается**.

## Возможности

- Приём файла по пути (`.exe`, `.dll`, `.bin`) или из стандартного ввода. Второй вариант позволяет
  анализировать образец ВПО прямо из архива, не записывая его на диск.
- Хэши MD5 / SHA-1 / SHA-256 (Windows CNG).
- Разбор PE: заголовки, секции, энтропия, таблица импорта, признаки упаковки, отсутствие ASLR и DEP.
- Извлечение строк: утилитой `strings.exe` (Sysinternals), если она есть, иначе встроенным методом
  (ASCII + UTF-16LE). Затем нормализация.
- Матрица из 55 сигнатур с привязкой к CWE, CVE и MITRE ATT&CK: ошибки, мета-данные, ключи реестра,
  команды, сетевые ресурсы, записки злоумышленника.
- Анализ машинного кода:
  - собственный декодер инструкций x86 / x64;
  - границы функций и граф вызовов;
  - модель стека, регистров и буферов: stdcall / cdecl, встроенные `strcpy` / `strcat`, результаты
    API, `sprintf`-подобные функции;
  - прототипы 91 функции WinAPI с расшифровкой констант (`FILE_ATTRIBUTE_NORMAL`,
    `HKEY_LOCAL_MACHINE`, `SW_SHOWDEFAULT`, ...).
- 13 видов цепочек поведения с техниками ATT&CK: массовое уничтожение файлов (T1485), снятие атрибутов
  (T1222.001), самокопирование в System32 (T1036.005), автозапуск (T1547.001), перебор дисков и каталогов
  пользователя (T1083) и др.
- Оценка риска (0–100 баллов) и вероятности инцидента ИБ, вывод, рекомендации и список индикаторов
  для блокировки.
- Отчёт в TXT (UTF-8) и таблица находок в CSV.

## Сборка

Нужна Microsoft Visual Studio 2026 (v145) с компонентом «Разработка классических приложений на C++».

- **Visual Studio:** открыть `ExeIAS.slnx` и собрать (платформы x86 и x64).
- **Командная строка:** запустить `build.bat`, результат появится в `build\ExeIAS.exe`.

Стандарт C++20, ключ `/utf-8`. Внешних зависимостей нет: используются стандартная библиотека и Windows API
(`bcrypt.lib`).

## Использование

```
ExeIAS.exe <путь к файлу .exe/.dll/.bin> [--name имя] [--internal]

  -           читать файл из стандартного ввода (образец не распаковывается на диск)
  --name      имя объекта в отчёте (для стандартного ввода)
  --internal  не вызывать strings.exe, извлекать строки встроенным методом
```

Примеры:

```bat
ExeIAS.exe C:\Windows\System32\notepad.exe

rem образец ВПО — прямо из архива, без записи на диск
tar -xOf Whiter.a.rar Whiter.a.exe | ExeIAS.exe - --name Whiter.a.exe
```

В текущем каталоге создаются:

| Файл | Содержимое |
|---|---|
| `report_<имя>.txt` | аналитический отчёт из шести блоков |
| `report_<имя>.csv` | все находки таблицей (открывается в Excel) |
| `strings_<имя>.txt` | извлечённые строки |

## Блоки отчёта

1. **Объект анализа** — хэши, формат, архитектура, дата сборки, секции, импорт, мета-данные.
2. **Признаки уязвимостей** — ошибки и исключения, CWE, CVE уязвимых библиотек, защитные механизмы PE.
3. **Индикаторы компрометации** — опасные функции, ключи реестра, пути, сетевые адреса, послания.
4. **Взаимодействие с файловой системой** — операции по таблице импорта, карта функций
   с восстановленными вызовами, граф вызовов, цепочки поведения.
5. **Оценка риска** — уровни находок, балл, вероятность инцидента, вывод.
6. **Рекомендации** — меры реагирования и индикаторы для блокировки.

## Пример: образец Whiter.a

Whiter.a — деструктивный троян 2001 года, замаскированный под генератор ключей Windows XP. ИАС разобрала
96 функций, восстановила аргументы 264 вызовов и нашла 12 цепочек поведения. Итог — CRITICAL, 100/100,
вывод «вредоносная программа деструктивного типа (троян-вайпер)».

Алгоритм образца, восстановленный по коду:

1. Мьютекс `WhistlerMutex` — защита от повторного запуска.
2. Первый запуск:
   - копия в `%SystemRoot%\system32\whismng.exe`;
   - автозапуск `HKLM\...\Run\Whistler = "...whismng.exe -next"`;
   - поддельный ключ `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` во временном файле, открытом в Блокноте.
3. Следующий вход в систему: в бесконечном цикле обходятся «Мои документы», все диски от `d:` до `z:`,
   доступные для записи, и диск `c:`. С каждого файла снимаются атрибуты, содержимое затирается копией
   шаблона `c:\wxp` («You did a piracy, you deserve it.»), затем файл удаляется.

Индикаторы из отчёта:

```
- SHA-256 fe974c995cfb27e8c91123081986847f6d3d4252b6a8d1e1385c558f2aeb7057
- файл "c:\wxp" с текстом «You did a piracy, you deserve it.»
- копия "%SystemRoot%\system32\whismng.exe"
- ключ "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
- параметр автозапуска "Whistler"
- команда автозапуска "%SystemRoot%\system32\whismng.exe -next"
- мьютекс "WhistlerMutex"
- файл "c:\zwxp"
```

Сам образец в репозиторий **не входит**.

## Проверка на легитимных файлах

| Файл | Балл | Уровень | Вывод |
|---|---|---|---|
| Whiter.a.exe (ВПО) | 100 | CRITICAL | деструктивная программа (вайпер) |
| sample_dropper.exe (демо ПР №7) | 97 | CRITICAL | нужен углублённый анализ |
| cmd.exe | 53 | HIGH | нужен углублённый анализ (инструмент двойного назначения) |
| notepad.exe | 32 | HIGH | функции двойного назначения, вредоносность не установлена |
| ConsoleApp28.exe (.NET) | 20 | MEDIUM | стандартное приложение .NET |
| xcopy.exe | 2 | LOW | потенциальные слабые места |

## Структура репозитория

```
ExeIAS.slnx              решение Visual Studio
build.bat                сборка из командной строки
ExeIAS/
  main.cpp               порядок работы модулей, аргументы командной строки
  input.h / .cpp         приём файла, хэши, строки, нормализация (раздел 2.1 ТЗ)
  pe.h / .cpp            разбор заголовков PE и таблицы импорта
  disasm.h / .cpp        декодер инструкций x86 / x64
  fsanalysis.h / .cpp    анализ взаимодействия с ФС: вызовы и их аргументы, цепочки поведения
  signatures.h / .cpp    матрица сигнатур, CWE / CVE / ATT&CK (раздел 2.2 ТЗ)
  report.h / .cpp        оценка риска и отчёт (раздел 2.3 ТЗ)
  common.h / .cpp        общие структуры данных
doc_tools/               скрипты сборки текста курсовой (рисунки, docx, оглавление через Word)
```

## Ограничения

- В 64-битном коде часть аргументов остаётся неизвестной (`?`): значения часто приходят из регистров,
  заполненных далеко от вызова.
- Упакованные файлы анализируются только по заголовкам и импорту.
- Для сборок .NET разбирается только машинный код загрузчика, IL-код не анализируется.
- Границы функций определяются эвристически, код разбирается линейно, без полного графа управления.
- Выводы статического анализа о поведении в конкретной среде следует подтверждать динамическим анализом
  в изолированной виртуальной машине.
